运行本项目需要安装以下软件：

## 1. Node.js

Node.js 用于运行聊天室后端服务器（聊天、图片上传、图片访问都在这里）。

安装完成后，可以在命令行中执行：

```
node -v
npm -v
```

如果能够正常显示版本号，则说明 Node.js 安装成功。

## 2. Python

项目使用 Python 自带的 HTTP 静态文件服务器运行前端，同时 YOLO 目标检测也在 Python 里执行。

检查 Python：

```
py --version
```

如果能够显示 Python 版本号，则说明 Python 已安装。

### 2.1 YOLO 相关依赖（发图自动检测需要）

目标检测依赖 ultralytics，需要额外安装：

```
py -m pip install ultralytics
```

安装完成后可以这样验证：

```
py -c "import ultralytics; print(ultralytics.__version__)"
```

如果只是聊天、不需要自动检测，这一步可以跳过，图片仍然能正常发送，
只是图片下方会显示「检测失败」，左侧栏也会提示 YOLO 不可用。

### 2.2 模型权重文件

自动检测默认按下面的顺序寻找权重，找到第一个能用的就用它：

1. `../train/runs/detect/train-2/weights/best.pt`（仓库整合后的位置）
2. `train/runs/detect/train-2/weights/best.pt`（训练作业被拷进聊天室目录时的位置）
3. `weights/yolo26n.pt`、`yolo11n.pt`（官方预训练权重兜底）

仓库的目录结构是：

```
yolo-chat/
├── chat/               <- 聊天室（本目录）
│   ├── server.js
│   ├── yolo_worker.py
│   └── ...
└── train/              <- YOLO 训练作业
    └── runs/detect/train-2/weights/best.pt   <- 训练产出的权重在这里
```

**注意：仓库里不带模型权重。**
因为权重是训练产物（约 5MB 一个），仓库只保留源码，详细的取舍见根目录 README。
所以刚克隆下来时 best.pt 并不存在，需要先按 `train/README.md` 跑一遍训练把它生成出来，
自动检测才能用。在那之前聊天和发图都正常，只是图片下方会显示「检测失败」。

如果你已经有训练好的权重，也可以直接指定它的位置，不必放进仓库：

```
set YOLO_MODEL=D:\somewhere\best.pt
node server.js
```

## 3. 启动方式

### 方式一：一键启动（推荐）

双击 `start_ai.bat`。它会依次做这些事：

1. 尝试通过 WSL 启动 Dify（文本 AI）。没装 Dify 会跳过，不影响聊天室。
2. 检查 `node_modules`，如果该目录不存在，则自动执行 `npm install`。
3. 执行 `start "chat-backend" cmd /k node server.js`，在单独的窗口里启动后端。
4. 如果 `py` 可用，再执行 `py -m http.server 8080` 启动前端静态服务器。
5. 自动打开 `http://localhost:8080/index.html`。

后端窗口需要保持运行，关掉它所有连接都会断开。

### 方式二：手动分别启动

```
cd chat
npm install
node server.js
```

再开一个窗口：

```
py -m http.server 8080
```

然后浏览器访问 `http://localhost:8080/index.html`。

## 4. 后端启动时会输出什么

正常启动大概是这样：

```
数据库迁移完成：messages 表新增 type 列      <- 只有第一次升级老数据库时出现
[YOLO] 使用 Python 解释器：C:\Python314\python.exe（Python 3.14.7，已安装 ultralytics）
[YOLO] 正在加载模型，首次大约需要几秒...
服务器在 3000 端口跑起来了
聊天室前端：http://localhost:8080/index.html
图片上传接口：POST http://localhost:3000/upload
图片访问地址：http://localhost:3000/uploads/...
[YOLO] 模型加载完成：...\best.pt（80 个类别）
[YOLO] 自动检测已就绪
```

如果看到 `[YOLO] 未能启动`，说明 YOLO 不可用（通常是没装 ultralytics），
聊天和发图仍然正常，只是不会自动检测。具体原因会打印在下一行。

## 5. 端口说明

| 端口 | 用途 |
| --- | --- |
| 3000 | 后端：WebSocket 聊天 + 图片上传 + 图片访问 |
| 8080 | 前端：Python 静态文件服务器 |

如果 3000 被占用，后端会提示「3000 端口已被占用」，关掉占用它的程序再启动即可。

## 6. 怎么用图片检测

1. 加入一个房间。
2. 点输入框左边的 🖼 按钮选一张图，或者直接把图片拖进聊天区，也可以按 Ctrl+V 粘贴。
3. 输入框上方会出现预览条，按回车或再点一次 🖼 发送。
4. 图片会立刻出现在聊天里，先显示「上传中 x%」，然后变成「正在检测…」。
5. 几秒内 YOLO 会发出一条新消息，包含画好检测框的图片、检测到的类别标签和置信度。

左侧栏的「YOLO：已就绪」表示检测功能可用。

## 7. 出问题了怎么办

双击 `diagnose.bat`，它会把环境信息全部检查一遍并打印出来，
同时在项目目录下生成两个文件：

- `diagnose.log` —— 完整检查报告
- `backend_test.log` —— 后端试运行 8 秒的输出

把这两个文件的内容发出来就能定位大部分问题。

### 常见情况

**双击 bat 窗口一闪就没了**
说明脚本本身没跑起来。本项目所有 .bat 都刻意只用纯英文（ASCII），
因为 cmd.exe 按 GBK 编码逐字节读取 .bat 文件，如果里面写了中文（UTF-8 编码），
整个脚本会被解析成乱码然后立刻退出。修改 .bat 时请保持全英文。

**提示「端口 3000 已被占用」**
上一次的 `node server.js` 还没关掉。打开任务管理器结束所有 node.exe，
或者直接重启电脑，然后重新启动即可。

**窗口开了，但页面显示「连接出错」「连接断了」**
先看 `chat-backend` 那个窗口里有没有报错。
如果看到 `[YOLO] 未能启动`，那只是检测功能不可用，聊天和发图仍然正常。

**页面能开，图片也能发，但一直显示「正在检测…」**
说明检测卡住了。把 `chat-backend` 窗口的内容发出来看看。

**第 1 步出现 `Wsl/E_ACCESSDENIED`**
正常现象，说明 Dify 没能启动，不影响聊天室本身。
